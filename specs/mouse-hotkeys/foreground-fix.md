# 8.1.2 前台切换修复

## 用户复现

8.1.1.0 反馈：上一步操作游戏时，直接按鼠标侧键无法切屏；必须先点击预览小窗口，再按侧键才切换。以此为本轮验收目标，不再将录制或驱动映射当作当前故障。

## 机制与约束

现有窗口管理器丢弃 SetForegroundWindow 的结果；管理器无条件更新内部角色/高亮，并可能最小化原角色。同一内部角色的直切入口还可能直接跳过重新激活。已通过拒绝激活的窗口边界复现旧源码 1 PASS、6 FAIL。

Windows 对后台前台切换有资格限制；观察到低级鼠标事件不保证获得与系统键盘热键相同的激活资格。点击预览后可切的现象与此一致，但仍须真实玩家设备回测，不用纯假窗口断言代替原生成功。

- 普通激活先尝试，实际前台异步完成后才提交状态。只在系统明确拒绝时尝试临时连接当前前台输入线程。
- 所有跨进程前台调用/临时连接均在一个专用后台线程中执行，应用 UI 与鼠标 hook 线程不得连接到游戏线程。
- 单请求有界等待、过期停止后续步骤、最多一个进行中的请求。已进入 USER32 的调用不能安全取消；超时不杀线程，不无限新建线程，不宣称原生调用已取消。
- 连接前检查外部窗口响应、前台未被用户切走；连接成功后 finally 释放。不能在连接后的共享队列依赖 SendMessageTimeout 实现原生超时。
- 不生成 Alt、点击或键盘输入，不改系统前台锁超时，不提权，不向游戏注入组件。AttachThreadInput 会影响线程键状态，Ctrl/Alt/Shift 组合需单独实机验收。
- 切换失败时不修改内部角色、不假高亮、不最小化原窗口；日志记录失败阶段，不记录按键历史或鼠标轨迹。

## 验收

1. 新激活算法：拒绝→重试→成功、异步成功、连接失败/释放、超时和繁忙、有界窗口探测、前台变化取消。
2. 管理器：拒绝无副作用、成功单次提交、同角色失去前台后恢复、首次循环拒绝不写入。
3. 原有鼠标/键盘、分组、配置持久化、模态与配置复制完整回归。
4. 自有测试窗口原生调用与玩家鼠标/EVE 实测分别报告。公开发布包不代表玩家设备已经回测。

## 证据记录（2026-10-21）

- 旧实现：拒绝激活边界 1 PASS / 6 FAIL；新实现在该管理器边界通过，并增加被动刷新和本 UI 目标不等待自己的检查。
- 激活 worker：普通/异步成功、明确拒绝重试、释放失败自然退出、Dispose交接取消、过期/繁忙和低帧后台不提前误拒绝等检查通过。所有原生操作均在独立线程的可替换边界验证，不用假 native 成功冒充 OS 资格成功。
- 最终完整结果：outputs/focus-8.1.2.0-verified.log，父运行器 304 PASS / 0 FAIL，8 子进程均退出 0；累计 1,069 条 PASS。
- 保留失败的 outputs/focus-8.1.2.0-final.log：en-US 视口截图只有最小化标题栏，另首次650ms模态录制提前返回；具体外部触发未确认。裸 MainForm 无 Presenter，语言代码不设置最小化，且新 worker 检查晚于该故障；测试新增显式 Normal 状态准备与日志后重测，不删除/弱化原断言。
- 原生两个独立窗口实验 NOT RUN：系统拒绝初始测试窗取得前台，未转而连接其他应用线程。真实玩家设备/物理按键/EVE 仍待回测。
- 候选版按 prerelease 单独发布，不替代现有正式 latest；包与公开资产验证记录在工作区 outputs，保留旧发布。
